# Runbook — Accessing Observability (Grafana, Dashboards, Metrics)

How to log into Grafana, find the dashboards, and query metrics. For the architecture behind this see
[`../architecture/observability-current-state.md`](../architecture/observability-current-state.md); when
something's broken see [`observability-troubleshooting.md`](observability-troubleshooting.md).

---

## 1. Access Grafana

Grafana is **Tailscale-only** (internal NLB, no public exposure) at:

> **https://grafana.aws.refplat.org**

1. **Connect to Tailscale** (the tailnet that has the platform VPC subnet routes). See
   [`tailscale-vpn.md`](tailscale-vpn.md). Without it, the hostname won't resolve / won't route.
2. **Log in via Keycloak OIDC** (#592). Grafana's `auth.generic_oauth` is wired to the `platform` realm
   (`infra/modules/observability/main.tf`; the observability unit passes `grafana_oidc_issuer` from
   `keycloak-config`), and the `groups` claim drives Grafana's role mapping. Click **"Sign in with Keycloak"**
   and authenticate against Keycloak — no shared password.

   **Admin login is break-glass only.** The local admin password is generated by Terraform and stored in
   **Secrets Manager** (also mirrored to the in-cluster Grafana secret); use it only when OIDC is unavailable:

   ```bash
   aws --profile platform secretsmanager get-secret-value \
     --secret-id platform/observability/grafana-admin --region us-east-1 \
     --query SecretString --output text
   # user: admin   (or the admin-user / admin-password keys if JSON)
   ```

   TLS is a real cert (cert-manager / Let's Encrypt DNS-01) — no browser warning.

## 2. Dashboards

Dashboards are **provisioned as code** (sidecar-loaded ConfigMaps from
`infra/modules/observability/dashboards/*.json`) — don't hand-create durable dashboards in the UI; add JSON
to the module instead (see below).

**Shipped today** (under the provisioned folder):

| Dashboard | Source | Shows |
|-----------|--------|-------|
| **Platform Health** | custom (`platform-health.json`) | cluster vitals, API-server availability/latency, capacity headroom, + a **GitOps row** (ArgoCD apps healthy / out-of-sync) |
| **Platform Services APM / RED** | custom (`platform-apm.json`, P6) | per-service RED (rate / errors / duration) for the platform services, from the Beyla/OTel data |
| **Platform Cost (OpenCost)** | custom (`platform-cost.json`) | cluster/namespace cost allocation from OpenCost |
| **ArgoCD** | grafana.com 14584 (`argocd.json`) | ArgoCD controller/server/repo-server health, sync/app metrics |
| **Tier-1 bundled** | kube-prometheus-stack | Compute Resources (cluster/namespace/pod), Node Exporter, Kubernetes/API-server, CoreDNS, Prometheus/Alertmanager overview |

**Sources currently scraped** (so their panels have data): the cluster itself (kubelet/cAdvisor/node),
**kube-state-metrics**, **Kyverno**, **cert-manager**, **ArgoCD**, **External-Secrets**, and **mimir**'s own
components. Dashboards for **Cilium agent/operator** are deferred (avoids a CNI re-apply; Hubble metrics are
exposed but not yet scraped).

### Add a dashboard (as code)

1. Drop a `<name>.json` into `infra/modules/observability/dashboards/`. Re-point any hard-coded `datasource`
   to the provisioned uids: **`mimir`** (default, durable) or **`prometheus`** (recent/local).
2. (Optional) set a folder via the `grafana_folder` annotation convention.
3. Apply the `observability` unit — the module renders it into a labeled ConfigMap and the Grafana sidecar
   loads it within ~1 min.

## 3. Query metrics

Grafana's **default datasource is mimir** (full history, environment `platform`); **Prometheus** is selectable
for the last ~15 days / lowest-latency local queries. In Explore, pick the datasource and run PromQL, e.g.:

```promql
up{cluster="platform"}                              # everything Prometheus is scraping (note the cluster label)
count(kube_pod_info)                                # pods cluster-wide
histogram_quantile(0.99, sum(rate(apiserver_request_duration_seconds_bucket[5m])) by (le))
sum(argocd_app_info{health_status="Healthy"})       # ArgoCD healthy apps (GitOps panel source)
```

**Tenancy note:** mimir requires `X-Scope-OrgID` — Grafana's mimir datasource sets it (`platform`)
automatically. Querying mimir **directly** (bypassing Grafana) needs the header:

```bash
# from inside the cluster only (mimir is ClusterIP, NetworkPolicy-isolated to the observability ns)
kubectl --context platform exec -n observability deploy/mimir-querier -- \
  wget -qO- --header 'X-Scope-OrgID: platform' \
  'http://mimir-gateway.observability.svc/prometheus/api/v1/query?query=up'
```

### Make a workload appear in metrics

Expose Prometheus metrics and add a **ServiceMonitor** (Prometheus scrapes ServiceMonitors cluster-wide —
`serviceMonitorSelectorNilUsesHelmValues=false`). For platform add-ons this is typically a `metrics_enabled`
toggle on the component's module/unit (as done for ArgoCD + External-Secrets). For team workloads, the
self-service path (per-team ServiceMonitors + environment routing) lands with **P10** — until then, coordinate
with the platform team.

## 4. Alerting (what fires, where)

Curated per-component alerts shipped with **P4** (`infra/modules/observability/alerts/curated.yaml`) — a
maintained set of rules for cert-manager, Kyverno, ArgoCD, Loki/Tempo, Cilium, and the rest of the platform
add-ons. Routing is severity-based; for the full alert catalog and first-response notes see
[`observability-alerts.md`](observability-alerts.md).

| Alert class | Destination |
|-------------|-------------|
| `severity=critical` | **SNS → email** (the `admin_email`, via the `platform-alerts` topic) **+ Slack** (`#platform-alerts`) **+ PagerDuty** (page) |
| `severity=warning` | **Slack** (`#platform-alerts`) |
| `Watchdog` (always-on heartbeat) | dropped (external dead-man's-switch is a follow-up) |

A `critical` inhibits a matching `warning` (same `namespace`+`alertname`) so one incident doesn't
double-notify.

**EKS-disabled rule groups:** `kubeScheduler`, `kubeControllerManager`, `kubeEtcd`, `kubeProxy` are off by
design (managed control plane is unscrapeable; Cilium replaces kube-proxy) — don't expect those alerts.

**Confirm the email subscription** is `Confirmed` (AWS sends a one-time confirmation):

```bash
aws --profile platform sns list-subscriptions-by-topic \
  --topic-arn arn:aws:sns:us-east-1:829808296602:platform-alerts --region us-east-1 \
  --query 'Subscriptions[].{ep:Endpoint,status:SubscriptionArn}'
```

**Fire a test alert** (proves the Alertmanager→SNS path end-to-end; sends one email):

```bash
kubectl --context platform exec -n observability sts/alertmanager-kube-prometheus-stack-alertmanager -c alertmanager -- \
  wget -qO- --header='Content-Type: application/json' \
  --post-data='[{"labels":{"alertname":"AccessRunbookTest","severity":"critical"},"annotations":{"summary":"test"}}]' \
  http://localhost:9093/api/v2/alerts
# resolve it by re-posting the same alert with "endsAt" set to now.
```

Add new alerts as `PrometheusRule` CRs (Prometheus picks them up cluster-wide); route them by adding a
matcher to the Alertmanager config in the `observability` module.
