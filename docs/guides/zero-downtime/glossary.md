# Glossary — zero-downtime deployments

The terms used across these docs, defined once. For platform-wide terms see the
[platform glossary](../../glossary.md). Alphabetical.

**AnalysisRun / AnalysisTemplate** — Argo Rollouts objects that run a check during a rollout. The
`AnalysisTemplate` defines the query + `successCondition`; an `AnalysisRun` is one execution. The
zero-downtime gates are AnalysisTemplates.

**Availability defaults** — The always-on ADR-085 layer (graceful drain, PDB, topology spread,
replica floor) injected/generated by Kyverno on every environment workload. Independent of deploys.

**Beyla** — eBPF auto-instrumentation that emits RED metrics per workload with no app code, feeding
the SLOs and gates.

**Blue-green** — A deploy strategy that brings the new version up fully, health-checks it, then cuts
over the Service selector in **one step**. No traffic reaches a bad version; no Gateway plugin needed.
Contrast *canary*.

**Burn rate** — How fast a service is consuming its error budget, as a multiple of the sustainable
rate. `1×` exactly spends the budget over the SLO window; `≥ 2×` trips the freeze. Metric:
`slo:current_burn_rate:ratio`.

**Canary** — A deploy strategy that shifts a **weighted slice** of real traffic to the new version
(25 → 50 → 100%), watched by a gate, promoting only while healthy. Contrast *blue-green*.

**Error budget** — The allowed amount of failure under an SLO: `1 − objective` (a 99.9% SLO permits
0.1% errors). Spending it too fast (high burn rate) gates change.

**Error-budget freeze (W11)** — A **pre-flight** gate (canary step 0, before any traffic shifts) that
aborts the deploy if the service is already burning its budget `≥ 2×`. Answers *"is the service
healthy enough to deploy at all?"* Contrast the metric gate.

**Gate** — A health check that can pause/abort a rollout. Two exist: the pre-flight *error-budget
freeze* and the background *metric gate*.

**Graceful drain** — Letting a terminating pod finish in-flight work before exit. Here: an injected
`preStop` sleep (10s) holds the pod serving while the datapath deprograms, plus
`terminationGracePeriodSeconds: 30` — but draining in-flight requests is the app's `SIGTERM` job.

**maxSurge / maxUnavailable** (rollout) — Control how many extra/disrupted pods a step allows. The
trivial lower-stage canary uses `maxSurge: 1` / `maxUnavailable: 0` so even a 1-replica stage stays
up. (Distinct from the PDB's `maxUnavailable`.)

**Metric gate (W8c)** — A **background** gate that runs across the canary, watching the new version's
success rate (RED) and **rolling back automatically** if it drops below 95% repeatedly. Answers
*"is the new version healthy?"* Contrast the error-budget freeze.

**Mimir ruler** — The Mimir component that evaluates the per-app SLO recording rules, producing the
`slo:*` series the gates and dashboards read.

**PodDisruptionBudget (PDB)** — A `maxUnavailable: 1` budget auto-generated per workload so voluntary
disruption (node consolidation, upgrades, drains) can't evict all replicas at once.

**Progressive delivery** — The ADR-056 layer: every workload is a Rollout; prod changes are
canary/blue-green with gates and auto-rollback.

**RED metrics** — Rate, Errors, Duration — the request signals Beyla emits; the success rate the
metric gate reads is derived from them.

**Replica floor** — The `require-prod-replica-floor` policy: prod workloads must run `replicas ≥ 2`
(Enforced). A single replica can't be zero-downtime.

**Rollout** — An Argo `Rollout` (the CRD replacing a Deployment), carrying the pod template directly
and adding canary/blue-green strategy + analysis.

**`rollouts-pod-template-hash`** — The label the controller injects into the stable/canary Service
selectors to point each at the right ReplicaSet.

**`setWeight`** — A canary step that sets the percent of traffic to the new version, applied as a
weight on the HTTPRoute `backendRefs`.

**SIGTERM** — The shutdown signal a pod receives. Handling it (stop accepting, drain, exit) is the
**app's** responsibility; the injected graceful-drain window only buys time for the network to stop
sending new traffic.

**SLO / SLI** — Service Level Objective (target, e.g. 99.9% availability) / Indicator (the measured
ratio). Every prod environment gets a 99.9% availability SLO automatically; it drives the gates.

**Stable / canary Service** — The two ClusterIP Services a canary-ed app has; both are weighted
backends of its one HTTPRoute, and the controller swaps their selectors via the
`rollouts-pod-template-hash`.

**Traffic router (Gateway-API plugin)** — The argoproj-labs plugin that drives weighted HTTPRoute
`backendRefs` for the canary on the Cilium Gateway (no service mesh).
