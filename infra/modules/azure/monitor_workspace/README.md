# Azure Monitor Workspace Module

## Overview

This module creates an Azure Monitor Workspace, which serves as a container for storing and analyzing metrics data, particularly for Azure Managed Prometheus instances. It provides a centralized location for storing long-term metrics data and enables advanced querying capabilities.

## Features

- Creates an Azure Monitor Workspace with standardized naming convention
- Configurable resource group and location settings
- Consistent tagging support for resource organization
- Comprehensive input validation for all parameters
- Supports integration with Azure Managed Prometheus and Grafana

## Usage

```hcl
module "monitor_workspace" {
  source = "../../modules/azure/monitor_workspace"

  name                = "mw-prometheus-prod-eastus"
  resource_group_name = "rg-monitoring-prod-eastus"
  location            = "eastus"
  
  tags = {
    Environment = "Production"
    ManagedBy   = "Terraform"
    Component   = "Monitoring"
  }
}
```

### Production Monitor Workspace with Automatic Naming

```hcl
module "monitor_workspace" {
  source = "../../modules/azure/monitor_workspace"

  # Name will be auto-generated by Terragrunt using the naming module
  resource_group_name = "rg-monitoring-prod-eastus"
  location            = "eastus"
  
  # Variables for the naming module
  prefix      = "vip"
  environment = "prod"
  region_abbv = "eus"
  
  tags = {
    Environment = "Production"
    ManagedBy   = "Terraform"
    Component   = "Monitoring"
    CostCenter  = "Platform"
  }
}
```

### Monitor Workspace for AKS Monitoring

## Required Inputs

| Name | Description | Type |
|------|-------------|------|
| resource_group_name | The name of the resource group to deploy the Azure Monitor Workspace in | `string` |
| location | The Azure region where the Azure Monitor Workspace will be deployed | `string` |

## Optional Inputs

| Name | Description | Type | Default | Required |
|------|-------------|------|---------|:--------:|
| name | The name of the Azure Monitor Workspace (auto-generated if null) | `string` | `null` | no |
| tags | Tags to apply to the Azure Monitor Workspace | `map(string)` | `{}` | no |
| prefix | Prefix for resource names | `string` | `"centric"` | no |
| environment | Environment name for resource naming (dev, test, staging, prod, ops) | `string` | `"dev"` | no |
| region_abbv | Abbreviation for Azure region (used in resource naming) | `string` | `"eus"` | no |
| customer | Customer name (used in resource naming for multi-tenant resources) | `string` | `null` | no |

## Outputs

| Name | Description |
|------|-------------|
| id | The ID of the Azure Monitor Workspace |
| name | The name of the Azure Monitor Workspace |
| query_endpoint | The query endpoint for the Azure Monitor Workspace |

## Integration with Other Services

### Prometheus Integration

For collecting Prometheus metrics from AKS clusters:

```hcl
module "prometheus_dcr" {
  source = "../../modules/azure/prometheus_dcr"
  
  name                = "dcr-prometheus-aks"
  resource_group_name = module.resource_group.name
  location            = module.resource_group.location
  
  data_collection_endpoint_id = module.prometheus_dce.id
  data_collection_rule_id     = module.prometheus_dcr.id
  
  # Reference to this Monitor Workspace
  monitor_workspace_id = module.monitor_workspace.id
}
```

### Grafana Integration

For visualizing metrics from the Monitor Workspace:

```hcl
module "managed_grafana" {
  source = "../../modules/azure/managed_grafana"
  
  name                = "grafana-monitoring"
  resource_group_name = module.resource_group.name
  location            = module.resource_group.location
  
  # Configure Grafana to use this Monitor Workspace as a data source
  azure_monitor_workspace_integrations = [
    {
      workspace_id = module.monitor_workspace.id
    }
  ]
}
```

## Notes

- Azure Monitor Workspaces are primarily designed for use with Azure Managed Prometheus instances
- Name validation enforces Azure requirements: 3-90 characters, alphanumeric, hyphens, and underscores
- When name is not provided, it should be supplied by Terragrunt using the naming module
- The Monitor Workspace query endpoint is useful for connecting to visualization tools like Grafana
- Consider creating Monitor Workspaces in the same region as your monitored resources for optimal performance
- Monitor Workspaces have separate pricing from Log Analytics Workspaces
